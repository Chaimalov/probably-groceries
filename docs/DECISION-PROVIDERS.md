# Decision-first grocery recommendations

## What the audit found

Checking off a product writes a purchase to the selected list. Edits, undo and remote changes update that history through the shopping store and CloudKit journal. The old recommendation request depended on the local predictor's three-trip gate, six events per product and 32-product cap. A 0.85 cutoff then filtered provider answers. Lists with the decision flag suppressed all local suggestions. The old client accepted missing answers as a valid empty batch, and the view hid otherwise-valid batches offline. A list switch or edit during the debounce could strand a refresh until another event.

The diagnostic snapshot contained 231 purchases, 224 in the selected list, across 126 purchased product IDs in that list. Of those, 77 IDs appeared once. The old diagnostics showed 23 product evaluations with three or more distinct trips and nine with a local suggestion. The saved preparation draft was empty. The exporter rebuilt ShoppingData without copying decision batches, so the exported empty array cannot establish whether a batch was saved. The snapshot has no request or credential status, so the live incident cannot be attributed to a particular authentication, transport or model outcome.

## Provider contracts

| Provider | Request | Bounded selection |
| --- | --- | --- |
| [OpenAI Decisions](https://developers.openai.com/api/reference/resources/decisions/methods/create) | Bearer OpenAI API key, POST to `api.openai.com/v1/decisions`, model `gpt-6-luna`, string `input`, array of named questions with `choices` | Up to 400 questions; 2–255 values per choice; named `answers` array |
| [Jev via OpenRouter](https://openrouter.ai/blog/tutorials/how-to-use-jev/) | Bearer OpenRouter API key, POST to `openrouter.ai/api/alpha/decisions`, model `typesafe/jev-1.13`, string `state`, keyed questions with `criteria` | [Jev model constraints](https://jev-ai.org/docs/models/) of 20 questions and 2–24 labels per choice; keyed `answers` object. This route is alpha. |

The old Jev hostname was replaced by the documented OpenRouter route. Existing credentials stay in Keychain and must be reconfirmed for the new contract. This prevents a legacy Jev key from being forwarded to a different host. The connection test sends synthetic evidence only. No chat model, local predictor or alternate provider runs on failure. A missing answer, refusal, malformed JSON, unknown choice and a model choosing `none` have different outcomes. HTTP authentication, request rejection, rate limiting and network failures surface separately. Raw provider errors and keys stay out of logs and exports.

## Evidence and decisions

Each call receives the same context for one list. Retain up to 500 valid events from 180 days, newest first, with UTC purchase day, quantity, unit and a request-local product label. Day resolution preserves recurring patterns and same-day baskets while omitting precise times. An item with one event is eligible. Verified alias links combine histories, and already-active or deferred identities remain context but cannot be selected. No account, note, photo, list name or persistent UUID is sent. Data outside the window, bounded field lengths and the transport limits control payload size and cost. The snapshot's full 224 selected-list events fit the event window.

Ask the model for the best next item or `none`. For histories above a provider's choice limit, group every eligible identity deterministically, ask for each group winner with the complete context, and let the model compare winners. Refill the winning group for the next rank. Stop at `none` or five selections. The group protocol trades extra calls and possible sensitivity to group composition for explicit choices and full candidate coverage. It avoids both a hard confidence threshold and cross-question probability comparisons. A typical one-group refresh uses one to five calls; a multi-group refresh can use up to eleven. Every call consumes one of 20 daily device requests, including connection tests. Input is billed for each call under [OpenAI Decisions pricing](https://developers.openai.com/api/docs/guides/decisions) and [OpenRouter Jev pricing](https://openrouter.ai/typesafe/jev-1.13). At 6,000 input tokens per call, five uncached OpenAI calls at $0.10 per million input tokens would cost about $0.003. Actual token usage depends on the request.

The result is an ordered array of existing product IDs. The add action prefills the latest observed quantity in the product's current unit, or one when there is no compatible event. This is an editable shopping default. The choice APIs do not return a free-text rationale, so the app makes no claim about why a specific product was selected.

## Lifecycle and verification

One device sponsors a specific list under explicit consent. A network task is debounced, single-flight and scoped to the selected list, connection generation and input digest. A late reply is discarded after list, provider, authorization or evidence changes. Active-list or deferral changes suppress items immediately and make the full digest eligible for refresh after a cooldown. History changes invalidate the cache; a six-hour expiry and UTC day rollover bound age. A valid cached batch, including a valid empty decision, survives offline and can reach other devices through the existing list journal. Recipients need no provider key. Foreground scheduling handles expiry and bounded backoff, honoring Retry-After. Physical two-account sharing and real provider results require device/credential checks.

On an iPhone, open Settings → Smart Recommendations, choose OpenAI or Jev, consent for the selected list and test a valid provider key. Open New Shopping and check the suggested products. Add or dismiss an item directly and check that it disappears while other valid items remain. Try the same list offline, another list, and a device receiving the shared batch. The diagnostics view reports the last outcome and whether a batch was present. Legacy shopping records and user-entered or edited drafts still decode. Legacy cached model decisions are invalidated by the new contract.
